# 呼び出しの仕組み

どのバインディングも同じ C API をラップしているため、呼び出しの動作はどの言語でも同じです。違うのは名前だけで、Python、Node.js、Rust、C では `convert`、C# では `Convert` です。

## 読みと文節

読みとは、入力されたひらがなの文字列です。読みを変換すると文節に分かれます。各文節は読みの一部に対応し、優先度の高い順に並んだ候補を持っています。

| 文節 | 読み | 候補 |
|---|---|---|
| 1 | きょうは | 今日は、きょうは、教は、… |
| 2 | さむいですね | 寒いですね、さむいですね、サムいですね、… |

各文節の第一候補をつなげたものが、Mozc が最有力とする変換「今日は寒いですね」です。候補には、Mozc による日本語の注記（例: カタカナ）が付くこともありますが、ほとんどの候補には付いていません。

## 文節の長さ

文節の区切りは Mozc が決めますが、長さを渡して指定することもできます。長さはバイト数や UTF-16 のコード単位ではなく Unicode の文字数で、文節ごとに 1 つずつ渡し、合計が読みの長さと一致する必要があります。長さ `[3, 5, 2]` で変換すると、「ここではきものをぬぐ」は「ここで / はきものを / ぬぐ」に区切られ、2 番目の文節の候補には「は着物を」と「履物を」の両方が並びます。

IME でユーザーが文節の区切りを動かすときは、新しい長さでもう一度変換します。

## 文脈

`context` は読みの直前のテキストで、たとえばユーザーがすでに確定したテキストです。Mozc はこれを履歴として使うため、最初の文節を文の始まりではなく続きとして変換します。なければ空にしてください。

## 予測

`predict` は入力途中の読みの予測候補を返します。「ありがと」なら「ありがとうございます」「ありがとう」などです。結果は文節に分かれず、1 つのリストで返ります。

## 学習

ユーザーが変換を確定したら、`learn` で学習させます。渡すのは、読み、各文節の長さ、各文節で選ばれたテキストです。同じ読みを次に変換するとき、選ばれたテキストが第一候補になります。`learn` が受け付けるのは文節の候補にあるテキストだけで、それ以外があると何も学習せず false を返します。

`clear_learning` は学習した内容をすべて消します。`flush` は学習した内容をすぐにプロファイルへ書き込みます。閉じるときにも書き込まれます。

## プロファイル

プロファイルは、Mozc が学習した内容を保存するディレクトリです。存在しなければ作成され、ディレクトリを指定しなければ Mozc の既定の場所（Linux では、`~/.mozc` があればそこ、なければ `$XDG_CONFIG_HOME/mozc` または `~/.config/mozc`）を使います。既定の場所はインストール済みの Mozc が使うプロファイルと同じなので、アプリの学習内容を分けておくにはディレクトリを指定してください。

Mozc はプロファイルディレクトリをプロセス単位で保持するため、1 つのプロセスで開くプロファイルは 1 つだけにしてください。同じプロファイルを閉じてから開き直すのは問題ありません。

シークレットモード（incognito）は何も学習せず、プロファイルにも触れません。記録すべきでない入力に使います。

## エラー

要求どおりに処理できなかった呼び出しは、空のリストまたは false（C では `NULL` または `0`）を返します。理由は `last_error` で、「the segment lengths do not add up to the reading's length」のような英語の文として取得できます。決まった文なので入力された文字列が含まれることはなく、ライブラリが読みや学習データをログに出すこともありません。

ライブラリを読み込めない場合、C API のバージョンが異なる場合、Mozc を起動できない場合は、開く処理が失敗します。言語によって、例外になるかエラー値が返るかが異なります。

## スレッド

1 つのハンドルは複数のスレッドから使え、呼び出しは順番に処理されます。
